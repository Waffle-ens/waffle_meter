# 음성 팩 — 굽기 절차 (SOT)

스킬이 추가·변경돼 알림 음성을 새로 구워야 할 때 **여기부터 읽는다.** 이 문서가 절차의 단일 정본이다.

`../와순이/`, `../와붕이/` 의 클립을 만들어 낸 **레퍼런스 음성**이 이 폴더에 있다. 이 wav 가 곧 목소리의
정의이고, 잃어버리면 같은 목소리를 다시 만들 수 없다 — 새로 뽑으면 다른 사람 목소리가 된다.

`.csproj` 는 `Assets/voice/**/*.mp3` 만 싣는다. 이 폴더의 wav 는 배포판에 나가지 않고 저장소에만 남는다.

---

## 언제 구워야 하나

앱이 말할 수 있는 문구가 늘거나 바뀌면 굽는다. 트리거는 셋뿐이다.

| 트리거 | 예 |
|---|---|
| `Assets/json/buff_catalog.json` 에 버프 추가 | 게임 패치로 신규 스킬 |
| `WaffleMeter.Capture/FieldBossCatalog.cs` 에 필드보스 추가 | 신규 필드보스 |
| 발화 **문구 자체**가 바뀜 | 리드 타임 문구 수정, `SpokenName` 등록 |

⚠ **문구를 한 글자라도 바꾸면 그 줄의 클립은 통째로 무효다.** 파일명이 `sha256(발화문구)[:16].mp3` 라
문구가 곧 키다. 바꿨는데 다시 굽지 않으면 그 줄은 조용히 온라인 음성으로 떨어진다(인터넷이 없으면 무음).

`ShippedVoicePackTests` 가 이걸 상시 감시한다 — 앱이 말할 수 있는 문구를 앱과 같은 규칙으로 재구성해
팩과 대조하므로, 굽지 않으면 테스트가 빨개진다.

## 절차

### 0. 환경

**TTS 서버 (Pinokio)**

* Pinokio 를 설치하고 `Qwen3-TTS-Pinokio` 앱을 받는다 → `C:\pinokio\api\Qwen3-TTS-Pinokio.git`.
  Start 후 `http://127.0.0.1:7860` 가 뜬다.
* **Models 탭에서 `Base` 1.7B 를 먼저 내려받아야 한다.** 안 받아 두면 굽기가 첫 줄에서 죽는다.
  `Whisper tiny` 는 후보 채점(전사)에 쓰이는데 첫 호출 때 자동으로 내려받으므로 **그때 인터넷이 필요**하다.
  `VoiceDesign` 은 **목소리를 새로 만들 때만** 필요하다 — 정기 재굽기에는 안 쓴다.
* ⚠ **CUDA GPU 가 필요하다.** 앱이 `device_map="cuda"` 로 고정돼 있어 CPU 경로가 없다.
* 포트가 7860 이 아니면 `voice-bake.py --server http://127.0.0.1:<포트>` 로 넘긴다.
* ⚠ **`app/app.py` 의 sampling 패치가 살아 있는지 먼저 확인한다.**

  ```
  grep -n "temperature=0.65" C:/pinokio/api/Qwen3-TTS-Pinokio.git/app/app.py
  ```

  없으면 `tts.generate_voice_clone(...)` 호출에 `temperature=0.65, top_p=0.8` 을 넣는다(백업:
  `app.py.bak-*`). 라이브러리 기본값 0.9 는 느슨해서 **한국어 예사소리가 된소리로 샌다**
  (`전선`→`쩐선`, `근성`→`끈성`). Gradio API 파라미터가 아니라 앱 소스라, **앱을 업데이트하면 날아간다.**
  패치 후에는 서버를 다시 띄워야 반영된다.

**Python**

```
python -m venv C:\Users\<user>\waffle_meter-ttsvenv
C:\Users\<user>\waffle_meter-ttsvenv\Scripts\python -m pip install -r dotnet/Assets/voice/_source/requirements.txt
```

⚠ **venv 를 `%TEMP%` 아래에 만들지 말 것** — 지워진다. v2.11.2 를 구운 venv 가 임시폴더에 있어서
하마터면 잃을 뻔했다. `ffmpeg`·`ffprobe` 가 PATH 에 있어야 한다.

1단계(`voice-lines-export.py`)는 의존성이 없어 시스템 python 으로도 돈다. venv 가 필요한 건 **2·3단계**뿐이다.

### 1. 무엇을 구워야 하는지 확인

```
python dotnet/tools/voice-lines-export.py            # 요약
python dotnet/tools/voice-lines-export.py --missing  # 클립 없는 문구만
```

`발화 가능한 문구` 와 `클립 있음` 이 같아야 정상이다. **고아 클립**(아무도 안 찾는 파일)이 있으면
문구가 바뀐 흔적이니 함께 정리한다 — 실제로 버프 목록을 정리하며 24개를 지운 적이 있다.

**한 번에 다 못 구울 때:** `python dotnet/tools/voice-lines-export.py --write-baseline` 으로
`_source/unbaked.txt` 를 찍어 남은 구멍을 고정한다. 그러면 `ShippedVoicePackTests` 가 **그 밖의**
누락만 실패시키므로 테스트를 빨간 채 방치하지 않아도 된다. 구운 줄은 반드시 다시 찍어 지운다 —
이미 구워진 줄이나 앱이 더 이상 말하지 않는 줄이 남아 있으면 테스트가 잡는다. 전수 목록이어야 하므로
`--scope real` 로는 못 찍는다. 갭이 다 닫히면 파일을 지운다(현재 없는 게 정상이다).

### 2. 굽기

```
python dotnet/tools/voice-bake.py --pack 와순이
python dotnet/tools/voice-bake.py --pack 와붕이
```

클립이 없는 문구만 굽는다. 줄마다 즉시 기록하므로 **언제 끊어도 다시 돌리면 이어받는다.**
이어받기 판정은 **작업 폴더에 wav 가 있는가** 다.

산출:

| | |
|---|---|
| `docs/voice/masters/<팩>/<sha>.wav` | 24kHz 원본, **배속 전** |
| `docs/voice/masters/progress-<팩>.jsonl` | 줄마다 채택 시드 · 전사 · 억양 수치 |

⚠ **이 둘을 지우지 말 것.** 원본이 있으면 배속을 다시 정할 때 재굽기가 필요 없고, `progress` 의 시드
기록이 있어야 "같은 계열 줄의 시드를 옮긴다"(아래 *안 잡힐 때* #2) 를 쓸 수 있다. `docs/` 는
`.gitignore` 대상이라 저장소엔 안 실리지만 사라지지도 않는다.

줄당 시드 5개 × (생성 + 전사)라 **420줄이면 3~4시간**이다. 몇 줄만이면 몇 분.

### 3. 설치 + 검수물

```
python dotnet/tools/voice-install.py --pack 와순이 --tag v2.11.3
```

배속을 걸고 팩 규격 MP3(44.1kHz · mono · 64kbps CBR)로 변환해 팩에 넣고, 검수용 mp3 와 시각 색인을
`%USERPROFILE%\waffle_meter-ttssamples\` 에 만든다. 누락·고아·규격도 함께 검사한다.

### 4. 듣기 — **이 단계를 건너뛰지 말 것**

검수 mp3 를 들으면서, 어색한 줄은 **색인 txt 에 괄호를 열어 적는다.**

```
[02:52.91]  선풍각 온 ('선풍각'이 '썬풍각'으로 발음됨)
[06:30.03]  세개의 뿔 마이노, 10분 뒤 리젠 ('세개의 뿔 마이노' 억양 어색함)
```

자동 점검(`※` 표시)은 참고일 뿐이다. **지표와 귀는 실제로 여러 번 어긋났다** — 아래 "믿으면 안 되는 것" 참고.

## ⚠ 레퍼런스가 지켜야 할 두 가지

둘 다 2026-08-24 에 실측으로 알아낸 것이고, **첫 굽기(v2.11.0)는 둘 다 어겼다.** 레퍼런스를 새로
만들 일이 생기면 여기부터 본다.

**1. 완결 평서문이어야 한다.** 복제 모델은 레퍼런스의 **억양 스타일까지** 복사한다. 옛 와순이 레퍼런스
`감시자 카이라, 10분 뒤 정각 출현 가능` 은 명사로 끝나는 조각이라 종결 하강이 없었고(끝기울기 **+16.2**,
즉 올라간다), 그 버릇이 420줄에 그대로 옮아 **문장 끝이 올라가는 줄이 60개**였다. 와붕이 레퍼런스는
완결 평서문이고(−21.3) 억양 편차가 절반이다. 하강 종결로 바꾸자 같은 지표가 **60 → 6** 으로 떨어졌다.

**2. 팩의 어떤 문구와도 겹치면 안 된다.** 겹치면 **그 줄만** 음색이 어긋난다. 옛 와순이는 레퍼런스
텍스트가 팩 문구와 글자까지 같아서 그 한 줄이 팩 중심에서 z=+2.1 로 튀었다(와붕이는 마침표 차이로
z=−0.4, 정상). 새 레퍼런스 문장은 **부분 포함까지** 대조해 고른다.

| | 와순이 | 와붕이 |
|---|---|---|
| 레퍼런스 | `와순이.wav` (7.91s) | `와붕이.wav` (2.62s) |
| 레퍼런스 텍스트 | `준비가 끝났습니다. 곧 시작하겠습니다. 자세한 내용은 화면에서 확인하실 수 있습니다.` | `슈고 페스타. 5분 뒤 시작합니다.` |
| 배속 | 굽기 뒤 `atempo=1.10` | 없음 |

`ref_text` 는 **레퍼런스 오디오를 그대로 옮긴 것이어야 한다.** 실제 발음과 다른 글자를 넣으면 문맥이
오염된다(와붕이 쪽 마침표가 남아 있는 것은 그 오디오가 실제로 그렇게 끊겨 읽히기 때문이다).

**말속도는 레퍼런스를 따라가지 않는다.** 레퍼런스를 1.16배로 늘려 복제해 봤더니 산출물이 오히려 미세하게
느렸다. 속도는 굽고 나서 `atempo` 로 맞춘다(음높이는 그대로, 시간축만).

## 후보 고르는 법 — 순서가 핵심이다

`voice-bake.py` 가 줄마다 시드 5개(한글 3음절 이하는 `네, ` 접두 후보 2개 추가)를 만들고 이렇게 거른다.

1. 길이가 정상 범위인 것만 — 폭주 배제. 한 문구에서 **163초짜리**를 뱉은 적이 있다
2. **Whisper 전사 유사도가 그 줄 최고치의 0.08 이내인 것만** ← 발음
3. 그중 끝이 내려가는 것 (`end_slope < 0`) ← 한국어 평서문의 불변량
4. 남은 것 중 억양 z-거리 최소 ← 팩 중심으로 당겨 분산을 줄인다

**2번을 빼면 안 된다.** 억양만 보고 골랐더니 된소리가 새는 줄이 **5 → 13** 으로 늘었다
(`저지`→`짜지`, `징벌`→`징발`). 전사는 판정에는 못 쓰지만 **같은 문구의 후보들 사이 순위**에는 쓸 수 있고,
그게 발음이 무너진 후보를 걸러낸다.

억양 특징값은 전부 **그 클립 자신의 중앙 음높이 대비 반음**이라 음색·음높이와 무관하다. 목소리가 바뀌어도
같은 잣대로 쓸 수 있다.

**1번의 실제 수치** (초/글자, `voice-bake.py` 의 `PACKS[...]["rate"]`):

| | 하한 | 상한 |
|---|---|---|
| 와순이 | 0.13 | 0.34 |
| 와붕이 | 0.16 | 0.42 |

여기서 다 걸러지면 조용히 무장해제되고(`or cands`) 전체 후보로 넘어간다.

**4번의 '팩 중심' 이란**: 그 팩 폴더에 이미 있는 mp3 를 파일명 정렬 앞 150개까지 재서 낸 평균·표준편차다.
20개 미만이면 하드코딩 기본값(head_level 0.9 / end_level −2.1 / end_slope −25.0 / rng 8.1)으로 떨어진다.

⚠ **목소리를 갈아엎는 굽기에서는 이 기준이 '옛 목소리의 분포' 다.** 이번 와순이 재녹음이 정확히 그
상태에서 돌았다 — 결과가 나쁘지 않았지만, 팩을 비우고 구우면 기준이 기본값으로 바뀌어 결과가 달라진다.
새 목소리를 앉힐 때는 이걸 알고 시작할 것.

## ⚠ 판정 근거로 쓰면 안 되는 것

이 팩을 만들면서 **지표와 귀가 세 번 어긋났다.** 전부 자동 판정을 믿었다가 틀린 사례다.

| | 왜 못 믿나 |
|---|---|
| **Whisper 전사** | 게임 고유명사를 모른다. 멀쩡한 클립을 `선풍가군`·`피성군 이쁜인` 으로 옮긴다. **순위 매기기까지만.** |
| **F0(음높이) 추정** | 300Hz 위에서 옥타브 오류. 피치를 1.04배 **올린** 파일을 "내려갔다"고 보고했다(사인파로 검증하니 필터가 아니라 추정기가 틀렸다). 낮은 음역(와붕이 102Hz)에서는 맞는다. 음높이를 다뤄야 하면 절대값 대신 **반음 단위 시프트**로 조작하고 귀로 확인한다. |
| **증상 겨냥 전사 매칭** | "'썬' 이 전사에 보이면 탈락" 식으로 짜 봤더니 16개 후보 전부에서 **0건 검출**됐다 — 이미 틀렸다고 판정된 클립까지 포함해서. 전사가 그 층위를 분간할 정밀도가 없다. |

극단적인 사례: `피송곳니 프닌` 을 멀쩡한 5분짜리의 시드로 옮겨 잡았을 때, **지표는 전부 나빠졌다**
(z 0.67 → 2.32). 그런데 귀로는 그게 맞았다. **판정은 듣는 것뿐이다.**

## 안 잡힐 때

시드를 아무리 돌려도 특정 발음이 안 잡히면 순서대로 시도한다.

1. **시드를 더** — `--seeds` 로 새 시드를 넣는다. 대개 여기서 해결된다
2. **같은 계열의 멀쩡한 줄의 시드를 옮긴다** — `피송곳니 프닌` 5분짜리가 멀쩡하고 10·30분이 이상하면
   5분짜리 시드(`progress-*.jsonl` 에 기록돼 있다)를 그대로 쓴다. 같은 이름·같은 문맥이라 잘 옮겨 간다
3. **접두어-트림** — `네, ` 를 붙여 생성한 뒤 첫 무음 경계에서 잘라낸다. 3음절 이하 짧은 줄이 무너질 때
   듣는다. ⚠ `voice-bake.py` 는 **한글 3음절 이하 줄에만** 자동으로 시도한다(420줄 중 17줄, 전부
   2음절 버프 + `온`). 긴 줄의 첫 음절 더듬기(`경계의 방랑자 파르곤` → `경경계의`)에 이 기법을 쓰려면
   스크립트의 `short` 판정을 손대야 한다
4. **표기를 바꾼다** — 읽는 소리가 표기와 다르면 `SpokenName` 에 등록하고 **그 읽는 소리로** 굽는다
   (`별동대장 링크스` → `별똥대장 링크스`). ⚠ **필드보스에만 적용된다** — 버프 음성은 `b.Name` 을 그대로
   읽으므로 버프 표기를 바꾸려면 코드를 손봐야 한다

### 알려진 실패 모드

* **된소리 누출** — 예사소리(ㄱㄷㅂㅅㅈ)가 된소리로. `temperature` 패치가 첫 방어선, 후보 선택 2번이 두 번째
* **사이시옷 삽입** — `피송곳니` → `핏송곳니`. 붙여 쓴 합성어에서 난다
* **첫 음절 더듬기** — 접두어-트림으로 잡는다
* **폭주** — 한 문구가 100초 넘는 오디오가 된다. `voice-bake.py` 가 8초 넘으면 그 후보를 버린다
* **3음절 이하 불안정** — 레퍼런스가 긴 문장인데 타깃이 극단적으로 짧으면 무너진다
* **`TTS 서버가 오디오를 돌려주지 않았습니다`** — 서버가 생성을 거부한 것이다. 모델이 안 올라왔거나
  (Base 1.7B 미다운로드) GPU 를 못 잡은 경우다. Pinokio 콘솔 로그를 볼 것

## 파일명 규약

`sha256(발화문구.strip())[:16] + ".mp3"`. 앱이 문구로 직접 해시를 떠서 찾으므로 매핑 테이블이 없다.
`BakedVoicePack`(C#)과 굽기 스크립트(Python)가 같은 값을 내는지는 `BakedVoicePackTests` 가 지킨다.

## 저장소에 안 실리는 것들

`.gitignore` 대상이라 이 저장소를 새로 clone 하면 **없다.** 잃어버리면 이 문서만으로 다시 만들어야 하므로
절차·기준·수치를 여기에 다 적어 두었다.

| | |
|---|---|
| `dotnet/tools/voice-{lines-export,bake,install}.py` | 스크립트 3종 (`/dotnet/tools/*.py`) |
| `docs/voice/masters/<팩>/*.wav` | 24kHz 원본 (와순이 420 · 와붕이 444, 약 111MB) |
| `docs/voice/masters/progress-<팩>.jsonl` | 줄마다 채택 시드·전사·억양 수치 |
| `%USERPROFILE%\waffle_meter-ttssamples\` | 검수용 mp3 와 색인 |

저장소에 **실리는** 것은 `_source/` 의 레퍼런스 wav 3개 + 이 문서 + `requirements.txt`, 그리고
`../와순이/`, `../와붕이/` 의 mp3 다. 그것만 있으면 앱은 돌지만, 새로 구우려면 위의 것들이 필요하다.
