# 음성 팩 원본 (voice pack sources)

`../와순이/`, `../와붕이/`의 클립을 만들어 낸 **레퍼런스 음성**이다. 이 두 wav가 곧 목소리의 정의이고,
잃어버리면 같은 목소리를 다시 만들 수 없다 — 새로 뽑으면 다른 사람 목소리가 된다.

`.csproj`는 `Assets/voice/**/*.mp3`만 싣는다. 이 폴더의 wav는 배포판에 나가지 않고 저장소에만 남는다.

## 재생성 방법

엔진: **Qwen3-TTS 12Hz 1.7B Base** (Apache-2.0), 로컬 실행. 음색은 레퍼런스가 고정하고, 발음·억양은
샘플링이 정한다 — 그래서 레퍼런스만 있으면 문구가 늘어나도 같은 목소리로 이어붙일 수 있다.

| | 와순이 | 와붕이 |
|---|---|---|
| 레퍼런스 | `와순이.wav` | `와붕이.wav` |
| 레퍼런스 텍스트 | `감시자 카이라, 10분 뒤 정각 출현 가능` | `슈고 페스타. 5분 뒤 시작합니다.` |

- `ref_text`는 **레퍼런스 오디오를 그대로 옮긴 것이어야 한다.** 실제 발음과 다른 글자를 넣으면 문맥이
  오염된다(와붕이 쪽에 마침표가 남아 있는 것은 그 오디오가 실제로 그렇게 끊겨 읽히기 때문이다).
- 생성 파라미터: `temperature=0.65`, `top_p=0.8`. 라이브러리 기본값 0.9는 느슨해서 한국어 예사소리가
  된소리로 새는 일이 잦았다(`전선`→`쩐선`, `근성`→`끈성`). 낮추면 음색은 그대로고 발음만 표준 쪽으로 좁는다.
- 파일명 = `sha256(발화문구)[:16] + ".mp3"`. 앱이 문구로 직접 해시를 떠서 찾으므로 매핑 테이블이 없다.
  `BakedVoicePack`(C#)과 굽기 스크립트(Python)가 같은 값을 내는지는 `BakedVoicePackTests`가 지킨다.

## 문구가 늘어나면

게임 패치로 필드보스나 버프가 추가되면 그 줄만 새로 구워 넣으면 된다. 시드를 고정하면 결과가 비트 단위로
재현되므로 기존 클립과 어긋나지 않는다.

읽는 소리가 표기와 다른 이름은 `SpokenName`에 등록하고 **그 읽는 소리로** 구워야 한다. 등록만 하고
굽지 않으면 그 줄은 조용히 온라인 음성으로 떨어진다.

## 굽기 중에 확인된 것

- **문장 첫머리에서 첫 음절이 겹치는 일이 있다.** `경계의 방랑자 파르곤`은 시드를 15번 넘게 바꿔도
  `경경계의`로 나왔고 표기를 바꿔도 소용없었다. 앞에 `네, `를 붙여 생성한 뒤 첫 무음 경계에서 잘라내면
  사라진다 — 모델이 더듬을 자리를 만들어 주고 그 부분을 버리는 것이다.
- **3음절 이하 짧은 줄은 불안정하다.** 레퍼런스가 긴 문장인데 타깃이 극단적으로 짧으면 무너진다.
- **Whisper 전사는 판정에 쓸 수 없다.** 게임 고유명사를 모르기 때문에 멀쩡한 클립도 엉뚱하게 옮긴다.
  후보 순위를 매기는 데까지만 쓰고, 합격 여부는 사람이 들어서 정했다.
