# 은퇴한 음성 클립 — 지우지 않고 여기 둔다

앱이 더 이상 말하지 않게 된 문구의 mp3. **삭제 대신 보관**하는 자리다.

## 왜 별도 폴더인가

클립은 **발화 문구의 sha256 앞 16자**로 주소화된다(`BakedVoicePack.FileNameFor`). 그래서 문구가 한 글자만
바뀌어도 옛 클립은 **아무도 참조하지 않는 파일**이 되고, `ShippedVoicePackTests.No_pack_carries_a_clip_nothing_asks_for`
가 그걸 설치본 군살로 잡아낸다.

그렇다고 지우면 안 된다 — 이 파일들은 로컬 음성 모델로 굽고 시드·전사 유사도·억양까지 선별해서 얻은 자산이다
(절차는 `../voice/_source/README.md`). 그래서 `Assets/voice/` **밖으로** 옮긴다:

- `WaffleMeter.App.Wpf.csproj` 의 동봉 글롭이 `..\..\Assets\voice\**\*.mp3` 라 이 폴더는 **설치본에 안 실린다**.
- `ShippedVoicePackTests` 는 `voice/<팩>/` 만 훑으므로 고아 검사에 걸리지 않는다.
- git 이 계속 들고 있으므로 되살릴 때 바로 꺼내 쓸 수 있다.

## 되살리는 법

그 문구를 앱이 다시 말하게 되면(예: 몹 이름 교정이 되돌려지면) 해당 파일을 `../voice/<팩>/` 로 옮기면 끝이다.
파일명이 곧 문구 해시라 이름을 바꿀 필요가 없다.

24kHz 원본과 채택 시드는 `docs/voice/masters/<팩>/` 에 따로 남아 있다(비공개). 여기 mp3 가 없어도
`voice-install.py` 로 다시 만들 수 있지만, 굳이 다시 만들 이유가 없어서 그대로 보관한다.

그 이름의 진짜 주인 2600068 이 그대로 남아 문구를 계속 만든다.

**2026-09-02 에 두 팩 모두 구워 넣었다**(아래 항목의 카이라 3줄과 같은 배치). 그래서
`../voice/_source/unbaked.txt` 는 지웠다 — 갭이 0 이면 파일이 없는 게 정상이다.

문구가 통째로 틀려서 은퇴했다. 팩당 4줄 × 2팩 = **8개**.
